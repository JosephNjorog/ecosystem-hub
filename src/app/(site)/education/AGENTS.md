# Education

Rules for this area. The root `AGENTS.md` applies too.

## Education (`src/app/(site)/education/` - routes `/education`, `/education/[academy]/[course]/[module]/[lesson]`)
- **Academies** of courses → modules → lessons. First one: the **Entrepreneur Academy**, taken over from builders-hub (4 courses, 12 modules, 113 lessons; slugs unchanged, so `/academy/entrepreneur/*` there maps 1:1 to `/education/entrepreneur/*`). Public without sign-in; signed-in users get saved progress and course certificates (below).
- **Content is files in git**, one folder per academy: `_content/<academy>/academy.json` (title, tagline, description + the tree courses → modules → lessons with title/description, in reading order), one plain `.md` per lesson, `quizzes.json`, `flashcards.json`. A lesson file must be listed in `academy.json` to exist. **Adding an academy:** a new folder + one entry in `ACADEMIES` (`_lib/content.ts`); `tests/education.test.ts` validates every folder automatically and fails the PR on broken content: unique url-safe slugs, no empty course/module, no `.md` outside `academy.json`, every directive resolves, no unused quiz, every quiz variant answerable (valid, distinct answers the server accepts), and every course completable end to end.
- Lesson Markdown is plain GFM - **no MDX, no raw HTML** (not rendered). Widgets are one-line directives: `::youtube[id]`, `::quiz[id]`, `::flashcards[set]` (`splitLesson`); they also set the lesson's icon (`lessonKind`). The test checks every file exists, every directive resolves and no HTML is left.
- Lesson bodies are read from disk per request (`readLesson`; directive counts once per process, `lessonCounts`); `outputFileTracingIncludes` in `next.config.ts` ships them in the standalone build. YouTube via `youtube-nocookie.com` (CSP `frame-src`).
- **Quizzes are graded on the server** (`answerQuiz`), signed in only - the browser gets `publicVariants` (question, options, single/multi) and never the answers, hints or explanations of a question not passed yet (they come back from the action; passed questions open answered). Same rule as builders-hub: **3 wrong answers lock the question for 24h**, then the count starts over (`QUIZ_TRIES`, `QUIZ_LOCK_MS`, `quizLock` in `rules.ts`; `QuizAttempt` row per user + question). A try is taken with one conditional update *before* grading, so parallel requests can't get more guesses. A passed question can be practised (other variants) without limit. "Try another question" cycles the alternates (`quizVariant`); option order is a seeded shuffle (`optionOrder`, stable across SSR/hydration). Signed out, the questions are shown with a sign-in prompt.
- **Progress** (saved for signed-in users, `prisma/schema/education.prisma`): `LessonVisit` (opening a lesson, client `RecordVisit` → `recordLessonVisit`; `visitedAt` = resume point) and `QuizPass` (written by `answerQuiz` on a correct answer). Lessons are keyed `course/module/lesson` (`lessonKey`), quizzes by id - renaming a slug or quiz id in `_content` orphans saved progress. Rules are pure in `rules.ts`: a lesson is done when opened **and** all its quizzes passed (`lessonDone`); `progressOf` gives done/total and `resume` (first unfinished lesson after the last one opened, else the first gap). Visits, quiz tries and passes are not audited (telemetry); issuing a certificate is.
- **Signed out**, lesson visits are kept in this browser only (`_lib/local-progress.ts`, localStorage `team1-education:<academy>`, every access try/catch). After sign-in `SyncLocalProgress` asks (toast) before adding them to the account - on a shared device they may be someone else's; "Discard" clears them. `syncLocalProgress` skips unknown lessons and never moves a saved visit backwards (`visitsToSync`); local data is cleared only after a successful sync. Quiz answers are never synced (that would bypass the lock).
- **Certificates**: one per user + course (`Certificate`), issued by `claimCertificate` only when `progressOf(...).complete` **and** the profile is complete (`hasCompleteBasicProfile` - email sign-ups start with the email's local part as name, the profile step confirms the real one; the course page links there first). Name and course title are snapshotted at issue time. Public by id - `/education/certificates/[id]` (noindex) is the verification page, `/[id]/pdf` renders the PDF on demand (`_lib/certificate.tsx`, `@react-pdf/renderer`, cached per id + name in memory; Kanit (300/500/700) + logo in `_certificate/`, traced via `next.config.ts`; the background `public/education/certificate-background.jpg` is shared with the page's HTML rendition; Kanit has no italic file, so the PDF slants the name (`skewX`) like a browser does; the logo PNG is the brand `Team1_MAIN_WHITE` rasterised, since react-pdf can't embed SVG files). Kanit only covers Latin and Thai: `claimCertificate` refuses other names (`printableName`) instead of printing a blank one. The printed name is always the profile name: the owner fixes a typo in the profile, then `updateCertificateName` copies it onto the certificate (same id, link and issue date; audited `certificate.rename`). The owner can delete their certificate, a super admin can delete anyone's (`deleteCertificate`, audited) - both from the certificate page. The owner also gets "Add to LinkedIn" (`linkedInAddUrl`: LinkedIn's add-to-profile link, pre-filled with team1's company page and the verification link - a plain link, no API).
